# Paper 8 — Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

## Paper contribution

Lewis et al. introduce **Retrieval-Augmented Generation (RAG)**, a hybrid parametric/non-parametric architecture that combines a pretrained sequence-to-sequence generator with a dense retrieval index. Instead of requiring the model to encode all knowledge in its parameters, RAG retrieves external passages and marginalizes over them during generation.

## Method

- Retriever: **Dense Passage Retrieval (DPR)** bi-encoder. A query encoder scores document vectors by inner product.
- Non-parametric memory: a Wikipedia passage index; the paper's index contains about **21 million passages / 15.3B vector values**.
- Generator: **BART-large**.
- The document encoder/index is kept fixed in the main setup; the query encoder and generator are fine-tuned jointly.
- Retrieved passages are treated as latent variables.
- **RAG-Sequence:** one latent retrieved document supports the entire generated sequence.
- **RAG-Token:** different retrieved documents may contribute to different output tokens.

## Evaluation scope

The paper evaluates knowledge-intensive tasks spanning:

- open-domain QA: Natural Questions (NQ), TriviaQA (TQA), WebQuestions (WQ), CuratedTREC (CT);
- abstractive answer generation on MS MARCO;
- Jeopardy question generation;
- fact verification/classification on FEVER.

## Concrete results

Open-domain QA test exact-match results include:

- **RAG-Sequence:** NQ **44.5**, TQA **56.8 / 68.0** (depending on split), WQ **45.2**, CT **52.2**.
- **RAG-Token:** NQ 44.1, TQA 55.2 / 66.1, WQ **45.5**, CT 50.0.
- RAG-Sequence's 44.5 EM on NQ substantially exceeds the 28.9 result cited for T5-large despite RAG using far fewer trainable generator parameters than very large closed-book baselines; the external index supplies non-parametric memory.
- On open MS MARCO NLG, RAG-Sequence improves over BART by **2.6 BLEU and 2.6 ROUGE-L points**.
- In Jeopardy question generation, RAG-Token performs better than RAG-Sequence on Q-BLEU-1, and both outperform the BART baseline.

## Retrieval ablations

The retrieval component is causally important in the paper's ablations:

- Freezing the retriever reduces performance across tasks relative to learned query retrieval.
- Replacing dense retrieval with BM25 is worse on most tasks, especially open-domain QA, although BM25 performs well on FEVER because entity overlap is useful there.
- Increasing test-time retrieved documents monotonically improves RAG-Sequence QA in the studied range, while RAG-Token peaks around 10 documents.

## Qualitative behavior

RAG generations are more factual/specific and more diverse than BART-only generations in several comparisons. The retrieved memory also gives a potential route to updating knowledge without retraining all model parameters, because the external corpus/index can in principle be replaced or refreshed.

## Limitations and boundaries

- Retrieval quality is a bottleneck: irrelevant or missing passages can lead to incorrect generation even when the generator is strong.
- The main Wikipedia index is static; the system does not itself solve freshness, source trust, or web navigation.
- The document encoder is fixed in the main configuration because jointly updating it would require costly index refreshes.
- RAG-Sequence thorough decoding can require many forward passes for long candidate sets, creating computational overhead.
- Retrieving more documents affects both performance and runtime and can trade BLEU against ROUGE behavior.
- The paper evaluates retrieval-conditioned generation/classification, not browser interaction, pagination, dynamic DOMs, structured schema filling, provenance retention, or action safety.

## Relevance to the survey

RAG is a P1 enabling method for agents that need **external knowledge, evidence retrieval, and non-parametric memory**. It directly motivates retrieval components in web/data agents, but generalized web extraction requires additional mechanisms to discover sources, interact with websites, validate field-level outputs, and preserve provenance. Retrieval augmentation improves access to evidence; it does not guarantee that retrieved evidence is correct, current, or faithfully used.

## Synthesis statement

RAG couples a BART generator with dense retrieval over an external Wikipedia memory and reaches 44.5 EM on Natural Questions while improving generative tasks over BART; it is strong evidence for retrieval-enabled agent memory and grounding, but retrieval errors, static corpora, decoding cost, and the absence of interactive source validation prevent treating RAG alone as a generalized web-data agent.
