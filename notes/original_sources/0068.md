# Paper 17 — ReAct: Synergizing Reasoning and Acting in Language Models

## Paper contribution

Yao et al. introduce **ReAct**, a prompting paradigm in which an LLM interleaves free-form reasoning traces (“Thought”) with environment actions and observations. Instead of reasoning entirely inside the model or acting without an explicit reasoning trace, ReAct couples the two in a repeated feedback loop.

## Method

For knowledge tasks, the action space is deliberately small: Wikipedia `search`, `lookup`, and `finish`. The agent alternates reasoning and calls to these actions, receiving textual observations from the external source. For interactive tasks, ReAct uses analogous environment-specific commands in ALFWorld and WebShop.

The key architectural idea is not a learned controller but a **trajectory format**:

`Thought → Action → Observation → Thought → ... → Answer/terminal action`.

Reasoning is used to track subgoals, determine what information/action is needed next, and interpret observations. Acting grounds the reasoning in external evidence and permits correction when observations conflict with the model's internal assumptions.

## Knowledge-task results

On the paper's HotpotQA and FEVER prompting experiments:

- HotpotQA EM: Standard 28.7, CoT 29.4, CoT-SC 33.4, Act 25.7, **ReAct 27.4**. ReAct alone does not beat CoT on EM, but ReAct→CoT-SC reaches **35.1**.
- FEVER accuracy: Standard 57.1, CoT 56.3, CoT-SC 60.4, Act 58.9, **ReAct 60.9**; CoT-SC→ReAct reaches **64.6**.

The paper therefore does not support the simplistic statement that ReAct always has the highest benchmark score. Its strongest knowledge-task evidence is improved grounding and complementarity with internal reasoning.

## Failure analysis

The manual HotpotQA analysis uses 50 correct and 50 incorrect trajectories for each of ReAct and CoT (200 total). Among sampled failed trajectories:

- **CoT hallucination accounts for 56%** of failures.
- **ReAct hallucination is 0%** in that failure sample.
- ReAct instead shows **47% reasoning errors** and **23% search-result errors**.
- Among sampled successful trajectories, false-positive/hallucinated reasoning or facts are 6% for ReAct versus 14% for CoT.

This is a critical trade-off: external interaction reduces unsupported factual invention but introduces retrieval/environment failure modes and can constrain the flexibility of reasoning.

## Interactive decision-making results

- **ALFWorld:** best ReAct trial achieves **71% success**, versus 45% for Act and 37% for BUTLER. Even the worst ReAct trial (48%) exceeds the best Act/BUTLER trials. ReAct also outperforms the denser imitation-style ReAct-IM variant (71 vs 53 overall success).
- **WebShop:** ReAct obtains an average score of **66.6** and **40.0% success rate**, versus Act 62.3/30.1, imitation learning 59.9/29.1, and IL+RL 62.4/28.7. Human performance is 82.1/59.6.

These tasks are important because they require long-horizon interaction with sparse rewards rather than only text generation.

## Fine-tuning evidence

Prompted ReAct can be hard for smaller models to imitate because it combines reasoning and acting. The authors fine-tune on **3,000 ReAct trajectories** for HotpotQA; after fine-tuning, ReAct becomes the strongest of the compared Standard/CoT/Act/ReAct formats for the tested PaLM-8B/62B settings. This supports learning the reasoning-action interface rather than assuming a few demonstrations always suffice.

## Limitations

- ReAct still suffers from **reasoning errors** and retrieval/search failures; grounding does not guarantee correctness.
- Complex tasks with large action spaces may require more demonstrations than fit into the in-context window, explicitly noted in the conclusion.
- The Wikipedia API is a simplified textual interface rather than the heterogeneous, dynamic Web.
- ReAct generally follows one trajectory at a time and does not natively search multiple alternative plans; later methods such as LATS address this limitation.
- Action formats and demonstrations are environment-specific, and irreversible real-world actions need safeguards outside the prompting scheme.

## Relevance to generalized web automation and extraction

ReAct is a P0 architectural foundation because it establishes the core agent loop used by many web agents: reason about the goal, execute a browser/tool action, ingest the resulting observation, and update the plan. The failure analysis also motivates provenance and verification: external evidence reduces hallucination, but retrieval/interaction errors remain and must be explicitly detected.

## Synthesis statement

ReAct operationalizes the LLM agent as an interleaved reasoning–action–observation loop. It sharply reduces hallucination in the paper's sampled HotpotQA failures and reaches 71% ALFWorld success and 40% WebShop success, but it still has reasoning/retrieval failures and scales poorly with demonstration complexity—precisely why generalized web agents need explicit state verification, recovery, and planning beyond a single prompted trajectory.
