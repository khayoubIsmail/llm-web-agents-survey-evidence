# Paper 72 — Cognitive Architectures for Language Agents (CoALA)

## Paper contribution

Sumers et al. propose **CoALA**, a conceptual framework for understanding language agents as cognitive architectures rather than as a single LLM prompt. CoALA places the LLM inside a larger program containing working/long-term memories, internal and external actions, and a recurring decision procedure. The paper is conceptual/systematizing evidence, not a benchmark paper; its value is the explicit decomposition of agent state and control.

## Core architecture

CoALA defines four interacting capability groups:

1. **Memory** — working memory plus long-term episodic, semantic, and procedural memory.
2. **Grounding actions** — external interaction with physical environments, humans/agents, or digital environments such as websites/APIs.
3. **Internal actions** — retrieval, reasoning, and learning operations over memory.
4. **Decision making** — a repeated decision cycle that uses reasoning/retrieval to plan, selects an external grounding or internal learning action, executes it, observes the outcome, and repeats.

This cleanly separates the **language model** from the **agent**: the LLM is one callable reasoning component; persistence, external state, action execution, and control flow live in the surrounding architecture.

## Memory taxonomy

- **Working memory:** persistent symbolic variables for the current decision cycle, including observations, goals, retrieved information, and generated reasoning. It is broader than the LLM context itself because the program chooses what subset to place in each call.
- **Episodic memory:** prior trajectories/experiences that can be retrieved into working memory and can be written after new experience.
- **Semantic memory:** world knowledge, including external text databases or newly inferred knowledge.
- **Procedural memory:** implicit procedures in model weights plus explicit source code implementing actions and the decision procedure.

The paper explicitly warns that modifying procedural memory is riskier than writing episodic/semantic memories because generated code can introduce bugs or subvert intended behavior.

## Action taxonomy

CoALA divides the action space into:

- **External grounding actions**, which affect or query the world and convert feedback into working-memory observations.
- **Retrieval actions**, which read long-term memory into working memory.
- **Reasoning actions**, which use the LLM to transform working-memory contents into new intermediate information.
- **Learning actions**, which write experience/knowledge/procedures into long-term memory.

The paper argues that this action-space view is essential: internal cognitive operations should be treated as first-class agent actions, not hidden implementation details.

## Decision cycle and planning

During each decision cycle, code orchestrates reasoning and retrieval to **propose, evaluate, and select** candidate actions. The chosen grounding or learning action is executed, new observations enter memory, and the cycle restarts. This is more general than one-shot action generation: planning can iteratively propose/evaluate alternatives and can mix LLM reasoning with symbolic/code-based procedures.

## Mapping existing agents

The paper uses CoALA to reinterpret systems such as ReAct, Reflexion, Generative Agents, Voyager, SayCan, and Inner Monologue. This comparison shows that apparently different systems can be described by which memories they expose, which internal/external actions they support, and how their top-level decision loop is programmed.

## Open problems and safety

The forward-looking analysis is specific rather than generic:

- richer episodic/semantic/procedural memory organization and retrieval;
- learning/unlearning and meta-learning by modifying retrieval or program procedures;
- balancing action-space size against decision complexity;
- adaptive **metareasoning** to decide when the benefit of further LLM planning justifies latency/compute;
- calibration and human-in-the-loop mechanisms for uncertainty;
- mixing language reasoning with code-based planning;
- explicit **action-space safety**, because grounding actions can cause external harm and procedural-memory edits can cause internal harm.

The paper notes that most contemporary systems still use task-specific safety heuristics and that deliberate propose–evaluate–select decision procedures are underexplored.

## Limitations and evidentiary boundary

- CoALA is a **conceptual framework**, not an experimentally validated architecture with a single benchmark score.
- Categories necessarily simplify implementations and are based on the state of the rapidly evolving literature at publication time.
- The framework does not prescribe concrete algorithms for memory retrieval, verification, permission enforcement, or optimal planning budgets.
- Translating perception to text can discard visual/spatial information; the framework acknowledges VLM-based grounding but does not solve multimodal grounding itself.
- Self-modifying procedural memory is identified as risky rather than demonstrated as safe/reliable.

## Relevance to generalized web automation and extraction

CoALA is directly useful for the survey's architecture taxonomy. A web extraction agent can be described as a decision loop connecting: working state (current page/schema/coverage), semantic/episodic memory, browser/API grounding actions, internal reasoning/retrieval/validation, and learning from prior website interactions. It also clarifies why “LLM = agent” is technically inadequate: persistent state, browser control, provenance stores, validators, and safety gates are external architectural components.

## Synthesis statement

CoALA provides a rigorous conceptual decomposition of language agents into memory, internal/external actions, and a recurring decision procedure, making it particularly useful for structuring generalized web-agent architectures; its contribution is taxonomic and architectural rather than a quantitative performance claim, and it explicitly leaves retrieval quality, metareasoning, grounding, and safe self-modification as open problems.
