# Paper 73 — Language Agent Tree Search Unifies Reasoning, Acting, and Planning in Language Models

## Paper contribution

Zhou et al. propose **Language Agent Tree Search (LATS)**, an inference-time planning framework that extends ReAct-style language agents with Monte Carlo Tree Search (MCTS), an LLM-based value function, external environment feedback, self-consistency, and verbal reflection. Instead of committing to one autoregressive trajectory, the agent explicitly explores alternative action/reasoning branches and backpropagates outcome information through a search tree.

## LATS algorithm

Each node stores the original task plus action/reasoning and observation history. A search iteration executes six operations:

1. **Selection:** choose a promising leaf using UCT.
2. **Expansion:** sample multiple candidate actions/reasoning steps from the LLM and execute actions to obtain observations.
3. **Evaluation:** score each candidate with an LLM-generated state score combined with a self-consistency term.
4. **Simulation:** continue expanding promising states until terminal feedback is obtained.
5. **Backpropagation:** propagate the terminal reward through visited nodes.
6. **Reflection:** when a trajectory fails, generate a verbal diagnosis and store it with the failed trajectory for subsequent iterations.

The proposed value function is a weighted combination of an LLM score and self-consistency. Critically, evaluation occurs **after environmental feedback**, allowing the heuristic to use evidence external to the model's internal reasoning.

## Evaluation domains

The paper deliberately spans four distinct settings:

- HotPotQA multi-hop question answering;
- HumanEval and MBPP programming with generated tests/compiler feedback;
- WebShop interactive web navigation;
- Game of 24 mathematical reasoning.

This breadth is central to the paper's generality claim: the same search structure can operate over thoughts, code solutions, or web actions by changing the environment/action representation.

## Concrete results

- **HotPotQA:** reasoning-only LATS reaches 0.62 EM versus CoT 0.34, ToT 0.55, and RAP 0.60 in the reported GPT-3.5 setup. The acting/reasoning configuration reaches **0.71 EM**, more than twice the 0.32 ReAct result reported in the comparison.
- **HumanEval:** GPT-3.5 LATS reaches **83.8% pass@1**, compared with ReAct 56.9, Reflexion 68.1, ToT 54.4, and RAP 63.1. With GPT-4, LATS reaches **92.7%**, slightly above Reflexion's 91.0 and the 80.1 base GPT-4 result.
- **MBPP:** GPT-3.5 LATS reaches **81.1% pass@1**, versus Reflexion 70.0 and RAP 71.4.
- **WebShop:** across 50 instructions, LATS obtains an average task score of **75.9** and a reported success rate of 38%; the average score is 22.1 points above ReAct's 53.8. The environment contains about 1.18M products and 12k user instructions.
- **Game of 24:** the self-consistency term improves LATS from 0.40 to **0.44 success rate** in the reported ablation.

## Search and cost ablations

Search is not merely decorative. Replacing MCTS with a simpler DFS-like search under comparable sampling drops HotPotQA performance by about **0.21** in the relevant ablation. Removing or weakening the LM-scoring component also harms use of external feedback.

The cost analysis shows LATS still requires substantial inference-time search, but among tree-search baselines it often reaches success after fewer expanded nodes. On HotPotQA at k=50 trajectories, LATS reaches 0.61 with an average **66.65 expanded nodes**, compared with RAP 0.54/70.60 and ToT 0.49/84.05.

## Web-agent interpretation

WebShop is particularly relevant because the agent receives browser-like observations and chooses search/click actions. LATS improves partial goal satisfaction substantially, but its 38% binary success rate remains far below expert-human performance reported for WebShop and below some task-specific fine-tuned success-rate baselines. The result supports inference-time planning, not solved web autonomy.

## Limitations and safety

The authors explicitly identify two main limitations:

- **Higher computational cost** than simpler prompting methods such as ReAct/Reflexion because multiple branches and LLM evaluations are sampled.
- **State reversibility assumption:** MCTS assumes that the search can return to prior states. This is easy for text/code simulations but may fail for irreversible real actions.

Other important boundaries follow from the experiments:

- LLM-generated reflections can be generic and lead to local minima; WebShop analysis observes this issue for simpler reflection baselines.
- LM value estimates are heuristic and can be miscalibrated.
- The framework samples many candidate actions, which is unsafe without permission controls when actions have side effects.
- The impact statement notes that improved autonomous decision-making can facilitate harmful use and security risks such as malware execution.

## Relevance to generalized web automation and extraction

LATS is P1 evidence for **deliberative multi-path planning** in web agents. It addresses a real weakness of single-trajectory ReAct: inability to reconsider alternatives before/after failure. For schema-guided extraction, analogous search could explore alternative navigation paths or extraction strategies. However, production systems must constrain search to reversible/read-only operations where possible and require confirmations or transactional safeguards for irreversible actions.

## Synthesis statement

LATS upgrades single-trajectory language agents with MCTS, external feedback, value estimation and reflection, yielding 92.7% HumanEval pass@1 and a 75.9 WebShop task score; its gains provide strong evidence for deliberate search in agent planning, while its inference cost and dependence on reversible states are fundamental constraints for real web automation with side effects.
