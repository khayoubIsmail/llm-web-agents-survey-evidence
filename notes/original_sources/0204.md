# WorldCoder, a Model-Based LLM Agent: Building World Models by Writing Code and Interacting with the Environment

## Research problem and contribution

WorldCoder learns an explicit world model as Python code from interaction. The program must explain observed transitions while remaining optimistic that some plan can obtain reward; the paper formalizes this optimism as a logical constraint coupling program synthesis and planning.

## Method and evaluation

An LLM proposes or edits transition programs, a planner searches the learned model, and discrepancies between predicted and observed outcomes trigger model revision. Because the representation is executable, knowledge can be inspected, tested, and transferred by editing code. Experiments on gridworld and task-planning domains compare sample efficiency with deep reinforcement learning and inference cost with ReAct-style agents. Across the reported settings, WorldCoder learns with fewer environment interactions and can transfer rules between related environments. Results use three random seeds and 95% confidence intervals for the main comparisons.

## Limitations and critical assessment

The central assumptions are strong: state is symbolic and discrete, dynamics are deterministic, and a useful transition program lies within the synthesis language. Real websites contain hidden state, stochastic services, visual ambiguity, and irreversible actions. Program synthesis also uses substantial LLM compute and can encode a confidently wrong model. The interpretability advantage is real, but only if learned rules are continuously tested against observations.

## Relevance to the survey

WorldCoder supports executable world models for web agents. DOM/action transitions could be represented as code, yet uncertainty and state invalidation must be explicit rather than hidden behind a deterministic model.
