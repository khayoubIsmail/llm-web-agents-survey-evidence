# Ask-before-Plan: Proactive Language Agents for Real-World Planning

## Research problem and contribution

Ask-before-Plan formalizes proactive planning under incomplete or changing user information. The new benchmark requires an agent to recognize when clarification is needed, obtain information through tools or dialogue, and only then produce a feasible plan. The proposed CEP framework assigns these stages to Clarification, Execution, and Planning agents.

## Method and evaluation

The benchmark extends TravelPlanner with ambiguous requests and dynamic interactions. CEP uses trajectory tuning for clarification and static tool execution, followed by a planning agent that consumes the updated conversation and environment evidence. Comparisons cover direct prompting, ReAct/Reflexion-style methods, GPT-3.5, Mistral, and other open backbones, with separate measures for clarification, tool use, and final planning. Results show that decomposition improves the full proactive task, but also expose model-specific trade-offs: GPT-3.5 more often produces syntactically valid actions, while Mistral can score better on some action-quality measures.

## Limitations and critical assessment

Benchmark ambiguities are constructed and tool interfaces are controlled. The dynamic evaluation is limited by model context length, and errors compound across the three agents. Asking more questions can improve correctness while degrading user burden, a trade-off not captured by task success alone.

## Relevance to the survey

This is direct evidence that robust web automation needs an “ask before act” option. Systems should evaluate clarification accuracy and unnecessary-interruption cost separately.
