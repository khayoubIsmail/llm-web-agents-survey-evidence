# Steering Large Language Models between Code Execution and Textual Reasoning

## Research problem and contribution

This paper studies how an LLM should choose between natural-language reasoning and executable code. It argues that many math, logic, search, and planning tasks are exactly solvable by programs, yet existing prompts and code-interpreter interfaces do not reliably route problems to the better representation. It proposes three routing/refinement variants, with the strongest generating both code and text and asking the model to synthesize the better answer.

## Method and evaluation

Seven baseline steering methods and three proposed methods are evaluated with six model families across 14 tasks in mathematics, logical reasoning, robot planning, and symbolic computation. Each task has more than 300 trials, code runs under a fixed Python environment and timeout, and methods are compared by success rate plus normalized aggregate score, token use, and runtime. No single baseline dominates: forcing code can hurt when generated programs are wrong, while text-only reasoning fails on precise computation. The combined Code+Text+Summary method obtains the best average score (79.5) and average rank (2.50) across the six models, but multi-turn self-refinement helps code-heavy outputs more consistently than text-heavy ones and can degrade weaker models.

## Limitations and critical assessment

All selected tasks are intentionally code-solvable and mostly have automatically checkable answers, so the study does not estimate routing quality for ambiguous, perceptual, social, or open-web tasks where executing code may be inappropriate. The combined method spends more tokens and runtime, and the model judging its own code-versus-text candidates can share their errors. Aggregate normalization obscures substantial task-level variance. Generated-code security, sandbox escape, data access, and side effects are outside the evaluation even though they are central for deployed agents. Thus, better benchmark accuracy does not by itself justify unrestricted execution.

## Relevance to the survey

The paper supports adaptive tool routing: code execution can externalize exact search or calculation, but the routing and verification policy is itself a failure point. For web agents, code should run in a constrained environment and results should be validated before they influence external actions.
