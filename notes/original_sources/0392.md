# UI-Vision: A Desktop-centric GUI Benchmark for Visual Perception and Interaction

## Metadata and scope

- **Authors:** Shravan Nayak, Xiangru Jian, Kevin Qinghong Lin, Juan A. Rodriguez, Montek Kalsi, Rabiul Awal, Nicolas Chapados, M. Tamer Özsu, Aishwarya Agrawal, David Vazquez, Christopher Pal, Perouz Taslakian, Spandana Gella, Sai Rajeswar
- **Venue:** ICML 2025, PMLR 267:45817–45851
- **arXiv:** 2503.15661
- **Survey role:** S5.1 desktop/GUI-agent benchmark and diagnostic evaluation evidence; P2 supporting source

## Research problem

UI-Vision addresses a platform gap in GUI-agent evaluation. Most established agent benchmarks emphasize web or mobile interfaces, while desktop software is harder to benchmark because applications differ widely, data collection is expensive, and licensing can restrict redistribution. The authors therefore construct a license-permissive **offline desktop benchmark** that evaluates perception, structural UI understanding, and next-action prediction separately.

This separation is useful for diagnosing whether an agent fails because it cannot locate an element, cannot understand the larger interface structure, or cannot convert its understanding into the right action.

## Dataset and environment coverage

UI-Vision spans **83 open-source desktop applications across six domains**: Productivity, Development, Creativity, Education, Browsers, and Social Media/Entertainment. Human annotators execute realistic software tasks while the system records screen video and action logs. Keyframes are then densely annotated with UI element bounding boxes, OCR/text labels, and interactions and pass expert human review.

The main paper reports **450 recorded videos** and a benchmark total of roughly **8.2k query-label/action pairs**. There is a small internal count inconsistency in the paper: one paragraph reports 8,267 pairs, whereas Table 1 and another paragraph report **8,227**. The task-level counts provide a clearer decomposition: 1,772 Basic Element-Grounding pairs, 1,772 Functional pairs, 1,935 Spatial pairs, 311 Layout-Grounding pairs, and 3,191 Action-Prediction pairs, which sum to 8,981 if all task datasets are treated independently. Therefore the aggregate '8.2k' claim should be cited cautiously; the per-task figures are safer for precise survey statements.

The benchmark is deliberately offline: it evaluates screenshots and recorded human trajectories rather than rerunning every full application workflow online. This makes model comparison reproducible while retaining UI complexity from real desktop software.

## Task 1: Element Grounding

Element Grounding asks a model to localize a UI component from a text query. A prediction is correct when the predicted point falls inside the ground-truth bounding box. UI-Vision defines three variants:

- **Basic:** locate an element from a short direct description/label.
- **Functional:** identify an element from what it does rather than its literal label; functional descriptions are generated with GPT-4o and human-validated.
- **Spatial:** locate an element from a relation to another component, such as what lies directly above or beside a named element.

Basic and Functional each contain **1,772 query-label pairs**; Spatial contains **1,935**.

The results show that desktop grounding is hard even for specialized GUI models. The best closed-source VLM reported, Claude 3.7 Sonnet, reaches only **8.7%** overall Element-Grounding accuracy; the strongest open-source general VLM, MiniCPM-V-8B, reaches about **4.3%**. GUI-specialized models perform better: **UI-TARS-72B reaches 25.5%** and UGround-v1-72B about 23.2%, but absolute performance remains low. Spatial grounding is especially difficult, with the best reported model reaching only **14.9%**.

Performance improves for larger target boxes and degrades as the number/density of UI elements increases, indicating that small controls and cluttered professional software remain a major grounding bottleneck.

## Task 2: Layout Grounding

Layout Grounding evaluates higher-level UI structure. LLAMA-3.3-70B initially groups individual UI elements into non-overlapping functional/semantic regions; expert annotators then validate the groups and bounding boxes. The final layout dataset contains **311 human-verified query-label pairs from 77 platforms**, with each functional group typically containing 5–10 elements.

Models are scored with **IoU, precision, and recall**. General VLMs outperform GUI-specialized agents on this task, suggesting that training focused on element-level clicking does not necessarily teach structural layout understanding. The strongest IoU in the main table is **Gemini-1.5-Pro at 30.8**, with precision 67.8 and recall 36.9. Gemini-2.0-Flash reaches 28.3 IoU, while Qwen2-VL-7B reaches 24.3.

The analysis shows the same density effect as element grounding: layout IoU tends to rise with larger target regions and decline when many elements are present. Error analysis identifies inaccurate bounding-box extent, poor functional grouping, and superficial keyword/semantic matching as characteristic failures.

## Task 3: Action Prediction

Action Prediction uses human action trajectories. At each trajectory step, the model receives the current screenshot, task goal, and previous action history, then predicts the next action and its parameters. The benchmark contains **3,191 action-annotation pairs across 442 computer-use tasks**.

The action space includes Move, Click, Typing, Hotkey, and Drag. Click/Move and Drag use normalized spatial-distance and **Recall@d** metrics; Typing and Hotkey use exact correctness. A **Step Success Rate (SSR)** counts a step as correct only when the action type and all required metadata/coordinates are correct.

The random baseline obtains 0% click and drag recall. Among closed models, Gemini-1.5-Pro reaches **13.0% click/move Recall@d** and 1.6% drag recall, GPT-4o 4.4% and 1.5%, and Claude 3.5 Sonnet 4.8% and 1.1%. The specialized **UI-TARS-7B** achieves the best click/move recall in Table 5 at **19.7%** and an overall **21.4% SSR**, but drag recall is still only 3.1%.

This gap demonstrates that correct high-level intent does not imply correct spatial execution. Dragging is particularly weak, likely because motion-rich desktop interactions are less represented in web-centric training data.

## Planner-versus-grounding diagnostic

The authors run a useful ablation to separate planning from grounding for closed-source models. Instead of asking the model to predict exact coordinates, it outputs only a textual action such as 'click the file button'; a strong grounding model (UGround-v1) then maps that action to screen coordinates.

This raises click recall by roughly **2×–5×**: GPT-4o reaches **26.7%**, Claude about **26.9%**, and Gemini **25.0%**. The improvement suggests that these models often know *what* action should happen but fail to ground it accurately on the desktop UI. This is directly relevant to web/GUI evaluation because a monolithic task-success metric would not expose that distinction.

## Error analysis

The paper identifies three major Action-Prediction error sources:

1. **Poor grounding:** the predicted action is conceptually right but targets the wrong location.
2. **Insufficient platform knowledge:** the model does not understand application-specific UI semantics and hallucinates or selects the wrong action.
3. **Platform complexity/density:** visually dense professional interfaces with many small controls produce higher error rates.

UI-TARS shows an **85% error rate on Creativity applications** versus **72% on Education applications**, illustrating how interface complexity materially affects action prediction.

Element-grounding error analysis further highlights ambiguity between similar controls, confusion over functionality, and failures on small or densely packed targets. Cross-software analysis shows substantial degradation on rare applications, demonstrating that broad GUI training does not automatically generalize to unfamiliar professional software.

## Models and evaluation breadth

The experiments compare a broad mix of closed-source VLMs, general open VLMs, and GUI-specialized agents, including GPT-4o, Claude 3.5/3.7 Sonnet, Gemini 1.5 Pro/2.0 Flash, Qwen2/2.5-VL, MiniCPM-V, InternVL2/2.5, CogAgent, SeeClick, UGround, UI-TARS, OSAtlas, ShowUI, Aria-UI, and Aguvis. This diversity makes the main diagnostic conclusion more credible: specialization helps element grounding, but different model families remain weak on layout understanding, precise action execution, or both.

The appendices additionally examine screenshot resolution, common-versus-rare software generalization, latency/output-token/GPU cost, and planner-versus-grounder contributions. For example, UI-TARS-72B is relatively accurate but has substantially higher per-query latency than several smaller models, showing another accuracy-efficiency trade-off.

## Critical assessment and limitations

UI-Vision has several strengths for the survey. It uses human demonstrations from real desktop applications, provides dense labels rather than only terminal success, and decomposes agent competence into perception, structure, and action. That makes it a strong diagnostic benchmark for determining *why* a computer-use trajectory fails.

Important limitations are:

- It is **offline**, so it does not measure complete closed-loop recovery after a predicted action changes application state.
- Although the 83 applications are diverse, they are selected for open licensing and cannot represent every proprietary enterprise or operating-system interface.
- Action Prediction evaluates each human trajectory step as an independent prediction with history, which is more controlled than letting the agent generate its own full trajectory; compounding errors and self-recovery are therefore underrepresented.
- Functional and layout descriptions use LLM-assisted generation before human validation, so some benchmark semantics inherit model-generated phrasing even though humans filter them.
- Desktop results should not be treated as direct web-agent success rates. Their value for this survey is evidence about grounding, UI density, platform knowledge, action representation, and generalization.
- The paper contains differing aggregate pair counts (8,267 vs 8,227), so precise claims should use the explicit task-level counts or flag the discrepancy.

## Relevance to this survey

UI-Vision strongly supports separating **observation/grounding**, **planning**, and **action execution** in evaluation. The planner-grounder ablation is particularly relevant: when a capable grounder is inserted, closed-model click recall rises several-fold, showing that a failed GUI action can originate in localization rather than reasoning.

For schema-guided web automation, the benchmark also illustrates why element-level correctness matters. An agent can understand a target field or button semantically yet still fail because the UI is dense, the target is small, or the interface is unfamiliar. WADE-style evaluation should therefore avoid reducing such failures to a single end-to-end score.
