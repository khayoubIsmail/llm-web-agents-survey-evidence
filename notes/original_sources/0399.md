# FormFactory: An Interactive Benchmarking Suite for Multimodal Form-Filling Agents

## Metadata and scope

- **Title:** FormFactory: An Interactive Benchmarking Suite for Multimodal Form-Filling Agents
- **Authors:** Bobo Li, Yuheng Wang, Hao Fei, Juncheng Li, Wei Ji, Mong-Li Lee, Wynne Hsu
- **Year:** 2025
- **Venue:** ACM Multimedia 2025
- **DOI:** 10.1145/3746027.3758285
- **arXiv:** 2506.01520
- **Survey role:** S5.1 benchmark/evaluation evidence; P2 supporting source

## Research problem

The paper isolates **automatic form filling** as a distinct GUI-agent problem rather than treating it as ordinary navigation. The agent must align information from an external document or instruction with visually presented fields whose labels, layout, order, and interaction types vary across forms. In addition to text entry, an agent may need to handle dropdowns, dates, checkboxes, file uploads, multi-page forms, and other stateful widgets. This makes form filling a useful stress test for semantic alignment, visual grounding, and low-level interaction accuracy.

## Benchmark design

FormFactory provides an interactive browser-based simulation platform with a backend scorer and a paired dataset. The paper's benchmark description and Table 1 cover **25 form scenarios**, with **1,250 total instances**, **13,800 annotated field–value pairs**, and **279 form fields**. The scenarios span academic/research, professional/business, arts/creative, technology/software, finance/banking, healthcare/medical, legal/compliance, and construction/manufacturing settings. Table 1 covers **9 field-type categories**, including string/text inputs, dates, binary choices, dropdowns, descriptions, file uploads, multiple-choice inputs, checkbox inputs, and numerical inputs; multi-page structure is also represented.

The dataset uses 50 instances per form. For many form types, gold field values are sampled from the form schema and an LLM then generates natural-language context containing those values. Job-application instances use generated Markdown-style resumes. Academic-submission instances use real papers from the web, with metadata such as title, authors, and abstract extracted as targets.

## Task formulation and agent interface

The authors model form filling as a page-level sequential decision process over user context, an interactive environment, visual states, and actions. The agent observes the source document/instruction plus a screenshot of the current page and emits GUI actions. The primary atomic actions are **Click(x, y)** and **Type(text)**; complex widgets are composed from lower-level actions. The baseline adopts a greedy page-wise strategy that generates applicable actions for the current page and then advances.

The execution stack contains a web-form frontend, a backend scorer, and an MLLM-driven action generator/executor. Actions are executed with PyAutoGUI on Windows. This makes the benchmark relevant to web-agent evaluation because success depends on acting on a rendered interface, not merely generating the right textual value.

## Evaluation protocol

The zero-shot evaluation includes **six MLLMs**: GPT-4o, Gemini 2.5 Pro, Claude 3.7 Sonnet, Qwen-VL-Max, Grok 3, and Doubao-Vision-Pro-32k.

Two levels are reported:

- **Atomic evaluation:** individual field types. **Click** measures selection of the intended UI element, and **Value** measures content correctness. Value uses exact-match accuracy except for free-form Description fields, where BLEU is used.
- **Episodic evaluation:** end-to-end completion of the full form interaction.

An important metric caveat is stated by the authors: a Value prediction can count as correct when the value appears in the model output even if it was not entered into the correct UI field. They note that a stricter interaction-grounded value metric would produce lower scores.

## Main quantitative results

The main result is a large gap between semantic value prediction and reliable GUI execution. **Click accuracy is generally below 10%**, especially on structurally complex widgets such as checkboxes and dropdowns. Table 2 reports very low episodic accuracy for every evaluated model: GPT-4o **0.9%**, Gemini 2.5 Pro **0.4%**, Claude 3.7 Sonnet **0.0%**, Qwen-VL-Max **1.1%**, Grok 3 **0.0%**, and Doubao-Vision-Pro-32k **0.0%**. The best end-to-end result is therefore only **1.1%**.

The conclusion summarizes the same pattern: click success remains below 10% and end-to-end completion remains below 2%. This directly supports the claim that possessing the correct information is not sufficient for successful web interaction; grounding and execution remain separate failure points.

## Ruler-enhanced grounding ablation

To compensate for weak absolute coordinate prediction, the authors overlay horizontal and vertical ruler scales on screenshots. Ruler guidance generally improves click accuracy, especially on simpler forms with fewer UI elements. The gain is marginal on complex forms requiring many interactions, and absolute click accuracy remains low. The ablation therefore shows that explicit spatial references help local grounding but do not solve the full planning/alignment problem.

## Complexity and failure analysis

The in-depth analysis shows two consistent trends. First, Value accuracy declines as the number of fields grows, reflecting increased alignment and reasoning load. Second, click performance also deteriorates with denser forms and greater field-type diversity. The joint analysis reports the worst performance when both field count and field-type diversity are high, indicating a compounding effect. Visual grounding, coordinate prediction, and field–value alignment are the central bottlenecks.

## Limitations and critical assessment

FormFactory is valuable because it isolates a realistic, schema-like web task where success requires both information extraction and correct interface manipulation. It is directly relevant to generalized web automation and schema-guided extraction: the source document provides candidate values, the form defines an implicit target schema, and the agent must map values into heterogeneous UI fields.

Important limitations are:

- The environment is a controlled simulation rather than arbitrary live websites, so it omits authentication, anti-bot behavior, open-web distribution shift, and other deployment variability.
- Many instances are LLM-generated from predefined gold values, which improves controllability but may not reproduce the full distribution of naturally occurring user documents.
- The baseline is deliberately simple and zero-shot; the results diagnose contemporary general MLLMs under this protocol rather than establish the ceiling of specialized form-filling systems.
- The reported Value metric is lenient because it does not always require the correct value to be entered into the correct field.
- The paper contains an internal count inconsistency: the introduction/Table 1 describe 25 form scenarios whereas §3.1 says the platform covers 20 realistic forms. For survey use, the table-level dataset totals (25 forms, 1,250 instances, 13,800 pairs) are the more explicit evidence, but the inconsistency should be acknowledged rather than silently harmonized.

## Relevance to the survey

FormFactory supports the survey's distinction between **task completion**, **field/value correctness**, and **interaction reliability**. An agent may identify correct semantic content yet still fail because it cannot ground that content to the correct UI element or execute the required interaction sequence. It also motivates multi-level evaluation: atomic click/value scores reveal failure modes that a single end-to-end success number would hide.
