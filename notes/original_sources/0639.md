#### Detailed notes

- Argues that current benchmarks assume failure-free infrastructure, ignore adversarial manipulation, and are often static or closed.
- WAREX acts as a transparent network proxy between the agent and the benchmark website.
- It can inject network errors, server errors, JavaScript failures/delays, popups/overlays, and dynamic content variation.
- It supports URL matching, k-th occurrence injection, every-k injection, and random injection policies.
- It also logs efficiency metrics such as latency, API calls, input tokens, and output tokens.
- Evaluates on WebArena, REAL, and WebVoyager using SteP, REAL demo agent, and WebVoyager agent.
- Network errors are especially destructive: WebArena success drops by more than 70% under network error conditions.
- Prompting agents to refresh/retry improves results only partially; it does not recover original no-fault performance.
- Malicious popup experiments show very high failure rates: agents often click deceptive popups and continue on fake sites.
- Shows that robustness needs to include everyday web failures, not only benchmark task success.

#### Thesis relevance

This paper supports the S5.5 thesis claim:

```text
Web-agent failure is multi-layered.
It can arise from benchmark design, perception, action grounding,
planning, execution, recovery, evaluation, robustness, or deployment conditions.
```

For **LLM-based agents for generalized web automation and data extraction**, this matters because extraction agents must not only complete clicks. They must also remain reliable under:

```text
dynamic pages
wrong filters
incorrect navigation
incomplete forms
visual/DOM mismatch
long trajectories
network and server failures
malicious or irrelevant content
evaluation ambiguity
```

#### Limitation as thesis gap

The thesis-relevant gap is:

```text
diagnosing web-agent failure is improving,
but current systems still do not provide a complete reliability architecture for:
- robust perception
- safe planning
- precise grounding
- recovery from failed actions
- infrastructure-failure handling
- adversarial-page handling
- structured extraction verification
- source provenance
```

Therefore, this paper should be used as evidence that generalized web automation needs a reliability layer, not only stronger models.

#### Thesis-ready paragraph

WAREX contributes to S5.5 by showing that current web-agent limitations cannot be understood only through aggregate task success. Introduces a plug-and-play proxy framework that injects realistic web failures, adversarial popups, and dynamic content into existing web-agent benchmarks without modifying the agent or benchmark. The main result is that Injecting network errors, server errors, JavaScript delays, and malicious popups causes large drops in task success on WebArena, WebVoyager, and REAL, revealing that current agents are not robust under realistic web failures. For the thesis, this paper is important because generalized web automation and data extraction require reliability at multiple layers: the agent must understand the task, perceive the page, ground actions correctly, recover from failures, preserve evidence, and verify extracted outputs. However, WAREX diagnoses robustness but does not provide a full solution; for the thesis, it shows that deployment reliability requires fault-aware agents, recovery, safety filters, and robust extraction verification. Therefore, this work should be used to motivate a failure-aware architecture for web agents.
