### Detailed notes

- Introduces Online-Mind2Web: 300 realistic tasks over 136 websites.
- Shows WebVoyager can overestimate agent ability because many tasks are simple, limited to 15 websites, or solvable via Google-search shortcuts.
- A naive search agent solves 51% of sampled WebVoyager tasks but only 22% of Online-Mind2Web tasks.
- Evaluates SeeAct, Browser Use, Agent-E, Claude Computer Use 3.5, Claude Computer Use 3.7, and OpenAI Operator with human annotation.
- Reports that Operator and Claude 3.7 are strongest but still far from reliable: Operator 61.3%, Claude 3.7 56.3%.
- Shows performance collapses with task difficulty: harder tasks reveal long-horizon planning and exploration weaknesses.
- Introduces WebJudge: key point identification, key screenshot selection, and outcome judgment.
- WebJudge reduces the failure of final-screenshot-only or all-screenshot evaluators by preserving important intermediate evidence while avoiding token overload.
- Error analysis highlights filter/sorting errors, incomplete steps, navigation errors, misunderstanding, and other failures.
- Operator mainly struggles with filter/sorting and navigation errors; other agents often show weak exploration, repetitive behavior, and hallucinated unmet constraints.

### Thesis relevance

This paper supports the S5.5 thesis claim:

```text
Web-agent failure is multi-layered.
It can arise from benchmark design, perception, action grounding,
planning, execution, recovery, evaluation, robustness, or deployment conditions.
```

For **LLM-based agents for generalized web automation and data extraction**, this matters because extraction agents must not only complete clicks. They must also remain reliable under:

```text
dynamic pages
wrong filters
incorrect navigation
incomplete forms
visual/DOM mismatch
long trajectories
network and server failures
malicious or irrelevant content
evaluation ambiguity
```

---

### Limitation as thesis gap

The thesis-relevant gap is:

```text
diagnosing web-agent failure is improving,
but current systems still do not provide a complete reliability architecture for:
- robust perception
- safe planning
- precise grounding
- recovery from failed actions
- infrastructure-failure handling
- adversarial-page handling
- structured extraction verification
- source provenance
```

Therefore, this paper should be used as evidence that generalized web automation needs a reliability layer, not only stronger models.

### Thesis-ready paragraph

Illusion of Progress / Online-Mind2Web contributes to S5.5 by showing that current web-agent limitations cannot be understood only through aggregate task success. Shows that reported progress in web agents is partly inflated by weak benchmarks and unreliable automatic evaluation; introduces Online-Mind2Web and WebJudge for more realistic assessment. The main result is that Frontier agents perform much worse on Online-Mind2Web than self-reported WebVoyager scores; many agents are around 30% success, while Operator reaches about 61.3%, and WebJudge achieves about 85% agreement with human evaluation. For the thesis, this paper is important because generalized web automation and data extraction require reliability at multiple layers: the agent must understand the task, perceive the page, ground actions correctly, recover from failures, preserve evidence, and verify extracted outputs. However, Online evaluation is more realistic but remains expensive, website-dependent, and still relies on LLM-as-judge; for the thesis, it diagnoses benchmark reliability but does not itself solve agent robustness or extraction verification. Therefore, this work should be used to motivate a failure-aware architecture for web agents.
