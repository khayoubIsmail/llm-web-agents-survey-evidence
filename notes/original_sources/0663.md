### Detailed notes

- Separates web information aggregation from linear task-completion web navigation.
- Uses three components: Navigator, Extractor, and Aggregator.
- Adds an enhanced action set so the Navigator can backtrack and transfer control when aggregation is needed.
- Uses feedback-driven navigation: Aggregator feedback guides what the Navigator should explore next.
- Supports Direct API-driven Access using search APIs and text extraction.
- Supports Interactive Visual Access using screenshots and browser interaction when paywalls, logins, or visually dependent interactions appear.
- Evaluates on AssistantBench, FRAMES, and FanOutQA.
- Relevant to thesis because many extraction tasks require multi-source evidence, not one page.

### Concrete evidence verified from the full paper

Infogent decomposes open-ended web information aggregation into Navigator, Extractor and Aggregator components, with aggregator feedback steering further exploration. It explicitly supports two access regimes: text/search-API navigation plus scraping, and screenshot-based interactive visual browsing. On FRAMES under direct API access it beats the compared state-of-the-art multi-agent search framework by 7%; on AssistantBench under interactive visual access it improves over the compared information-seeking web agent by 4.3%. This makes it evidence for multi-source collection and aggregation rather than only linear task completion.

#### Author-stated / evidence-based limitations

The paper focuses on answer-level aggregation rather than schema-bound row extraction with field-level provenance. It also documents navigation failures, dependence on strong GPT-4-class components, dataset limitations and sensitivity to the dynamic Web.
