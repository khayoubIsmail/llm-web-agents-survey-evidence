# GuardAgent: Safeguard LLM Agents via Knowledge-Enabled Reasoning

## Research problem and contribution

GuardAgent proposes a separate guardrail agent that checks a target agent's logged inputs and outputs against natural-language safety or privacy requests. It converts a retrieved-example-supported plan into executable guardrail code and evaluates the design on two new benchmarks: EICU-AC for role-based healthcare access control and Mind2Web-SC for web-agent safety policies.

## Method and evaluation

The guardrail operates beside, rather than inside, the target agent. An LLM plans the check, generates code from a toolbox, debugs it if necessary, executes it, and either grants or denies the target action with an explanation. Experiments protect EHRAgent and SeeAct and report label accuracy, precision, recall, explanation accuracy, and final-response accuracy. Depending on the core LLM, GuardAgent exceeds 98% label accuracy on EICU-AC and 83% on Mind2Web-SC; with Llama-3.3-70B it reaches 99.1% and 93.0%, respectively. It maintains 100% final-response accuracy on allowed cases in the reported settings, whereas invasive hard-coded rules can sharply reduce task performance. Removing the relevant toolbox and memory lowers executable-code rate and EICU-AC accuracy, supporting their causal role.

## Limitations and critical assessment

The benchmarks encode static, author-specified rules and judge post-hoc logs, so results do not establish protection against prompt injection into the guard itself, obfuscated actions, incomplete logging, state races, or policies that require temporal and cross-session reasoning. Code execution improves determinism only after the LLM has interpreted the policy correctly; an erroneous plan can become a consistently enforced error. The same benchmark authors define policies, tools, and evaluation labels, and there is no field deployment or human-policy-author study. The claim of low overhead is not accompanied by a broad latency/cost analysis. The paper also gives no dedicated limitations section, so these boundary conditions must be inferred from its design and experiments.

## Relevance to the survey

GuardAgent illustrates an external policy-enforcement layer for web agents and the benefit of translating policy into inspectable, executable checks. It is relevant to action authorization and least privilege, but should be cited with the caveat that strong in-benchmark accuracy is not evidence of end-to-end security against an adaptive attacker.
