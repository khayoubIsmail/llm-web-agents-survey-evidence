### Concrete evidence verified from the full paper

SMCP proposes a protocol-level security extension to MCP built around five coupled mechanisms: unified digital identity/trust infrastructure, mutual authentication, continuous security-context propagation, fine-grained policy enforcement and structured audit logging. A Trusted Component Registry binds users, agents, models, tools and data services to auditable identities; session establishment verifies credentials and delegation chains, while each downstream invocation carries a security context used for least-privilege decisions. Audit records bind operations to call-chain identifiers, policy decisions, timestamps and signatures for end-to-end traceability. The paper maps common MCP risks—including unauthenticated access, resource poisoning, token passthrough and cross-tenant exposure—to these controls and provides a staged implementation/standardization roadmap.

#### Author-stated / evidence-based limitations

SMCP is a protocol architecture and design proposal supported by worked use cases and threat-to-control mappings, not a large-scale empirical attack/defense benchmark. Its security guarantees depend on correct registry governance, credential management, policy definitions and adoption across participating MCP components.
