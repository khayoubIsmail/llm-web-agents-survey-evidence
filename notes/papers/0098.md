### Paper-specific synthesis

#### Dataset and framework

ToolLLM builds a large executable tool-use pipeline around **ToolBench**. The authors initially crawl **10,853 tools / 53,190 APIs** from RapidAPI and filter them to **3,451 usable tools containing 16,464 APIs across 49 categories**. ChatGPT generates single- and multi-tool instructions and annotates solution paths with real API responses. The final training set contains **126,486 instruction–solution-path pairs** and **469,585 real API calls**.

A learned retriever selects relevant APIs from the large catalog. ToolLLaMA, fine-tuned from LLaMA on ToolBench, then reasons and calls APIs. To reduce single-path ReAct failure, the authors introduce **DFSDT**, a depth-first-search decision tree that can abandon a bad branch and explore an alternative.

#### Evaluation and concrete results

ToolEval measures **pass rate** (whether the instruction is successfully completed under a budget) and **win rate** against another solution. Its agreement with human annotations is reported as **87.1% for pass rate and 80.3% for win rate**.

The API retriever strongly exceeds BM25 and OpenAI ada embeddings: average **NDCG@1/NDCG@5 = 78.0/84.9**, compared with **18.5/17.0 for BM25** and **49.6/45.4 for ada**. ToolLLaMA outperforms text-davinci-003 and Claude-2 and is close to ChatGPT in the paper's tool-use comparison, while DFSDT improves complex multi-step completion over conventional ReAct. ToolLLaMA also transfers zero-shot to APIBench APIs it never saw during training, performing comparably to Gorilla in that OOD setting.

#### Relevance to Web agents

ToolLLM is strong evidence for Web agents that face **large, changing tool catalogs**. It separates API retrieval, planning, execution and evaluator design; supports multi-tool trajectories with real responses; and explicitly allows backtracking after execution failure. These are close analogues of browser-tool selection, navigation and recovery.

#### Limitations

RapidAPI endpoints can change or fail, and the authors explicitly note temporal API variability. The training/annotation pipeline depends heavily on ChatGPT-generated instructions and paths, while ToolEval itself is LLM-based. Passing a tool-use instruction does not certify safety or correctness of side effects. Structured APIs also expose cleaner affordances than arbitrary DOM/visual interfaces.

#### Evidence locations

#### One-sentence synthesis

ToolLLM scales tool-use training to 16,464 real APIs and demonstrates that retrieval plus backtracking search materially improves multi-tool execution, making it a strong precursor for large-toolset Web agents while retaining evaluator, API-drift and safety limitations.
