### Paper-specific synthesis

#### Contribution

SWE-agent argues that agent performance depends not only on the LLM but on the **Agent-Computer Interface (ACI)** through which it observes and edits an environment. The authors design compact commands for file search, viewing and editing that keep useful context local, reduce verbose shell output, and make repository navigation easier for an LLM.

#### Concrete results

Using GPT-4, SWE-agent resolves **12.5% of SWE-bench issues** and **87.7% of HumanEvalFix problems** in the reported evaluation. At the time, the cited prior best SWE-bench result was about **3.8%**. On a 300-instance SWE-bench subset, replacing the custom ACI with a default Linux-shell-style interface reduces performance by about **10.7 percentage points**, demonstrating that interface design is a causal contributor rather than a presentation detail. The main SWE-bench runs use an approximately **$4 per-instance** model-call budget.

Trajectory analysis shows that constrained editing/navigation commands reduce common failures such as losing location in long files, emitting malformed edits, or consuming context on unhelpful output.

#### Relevance to generalized Web agents

SWE-agent provides unusually direct evidence for a principle central to browser agents: **the action/observation interface is part of the agent architecture**. DOM/AX abstractions, element IDs, compact page representations and structured browser commands can materially change success even with the same underlying LLM. This supports evaluating grounding/action interfaces separately from model capability.

#### Limitations

Software repositories provide deterministic tests and textual structure that many Web tasks lack. SWE-bench issue resolution is also domain-specific, and 12.5% success leaves most real issues unresolved. The custom interface does not address visual grounding, permission-sensitive browser actions, provenance or changing remote pages.

#### One-sentence synthesis

SWE-agent demonstrates that redesigning the computer interface around an LLM can raise task success dramatically without changing the base model, making observation/action interface design a first-class variable for generalized Web agents.
