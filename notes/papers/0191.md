## Analysis

<!-- note-body-start -->
### Research problem and contribution

L2MAC addresses outputs too large to fit in an LLM context window. It represents a long task as a stored prompt program in an instruction registry and maintains intermediate and final artifacts in an external file store. A control unit schedules separate LLM agents and constrains their reads and writes, giving the system a von Neumann-style separation of program and memory.

### Method and evaluation

The prompt program decomposes a user task into executable instructions. Each instruction is handled by an agent with selected memory, while the control unit updates the shared store and prevents the full evolving artifact from occupying every context. Code-L2MAC is evaluated on large codebase-generation tasks against coding-agent baselines; the paper also demonstrates book-length generation. Analyses examine instruction design, memory access, output summarization, consistency, cost, and scaling. The cited 90.2% HumanEval Pass@1 figure characterizes the underlying code model rather than, by itself, proving system-level superiority and should not be misreported as the principal L2MAC result.

### Limitations and critical assessment

Performance remains bounded by the base LLM's planning and tool-use ability. Listing file names eventually creates another context bottleneck, and long generated artifacts can contain globally inconsistent assumptions that local checks miss. The book example is illustrative rather than a rigorous quality evaluation. Generated code also requires sandboxing and end-to-end tests.

### Relevance to the survey

L2MAC is useful for external memory and orchestration. Its separation of instructions, control, and persistent files maps naturally to long-running web extraction jobs, while highlighting the need for global consistency checks.
