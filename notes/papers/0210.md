## Analysis

<!-- note-body-start -->
### Research problem and contribution

NetPlay tests a zero-shot GPT-4 agent in NetHack, a substantially more dynamic and unforgiving game than many prior LLM-agent environments. The architecture selects from predefined skills, remembers prior interactions, and interrupts an executing skill when important game events demand replanning.

### Method and evaluation

The authors create isolated NetHack levels to test capabilities and run broader game-play evaluations involving partial observability, diverse items and monsters, and many terminal failure modes. Event detection is intended to make high-level planning responsive rather than blindly executing a stale sequence. Results show competence on selected short behaviours but poor reliability on sustained play; the agent struggles to build an accurate mental model, manage risk, and recover from novel situations.

### Limitations and critical assessment

The system depends on an engineered skill library and game-specific event detector, while calls to GPT-4 are costly and model-version dependent. NetHack is still a game with an explicit action interface, but it usefully reveals how zero-shot planning degrades under hidden information and irreversible mistakes. Negative results are therefore the main contribution.

### Relevance to the survey

Use as counterevidence to broad claims of generalist autonomy. In web automation, long-horizon success similarly requires event-driven interruption, state tracking, and recovery—not merely a capable high-level planner.
