#### Core idea

#### Key finding / main claim

Multimodal agents can complete smartphone tasks by combining visual perception, planning, and UI actions.

For S4, the important question is not only whether the method works on its benchmark, but **which part of web/GUI agency it improves**:

- perception and grounding,
- planning and reasoning,
- action execution,
- API/tool use,
- memory/state tracking,
- recovery and verification,
- or deployment/evaluation.

---

#### Concrete evidence verified from the full paper

- **Benchmark:** AppAgent evaluates **50 tasks across 10 Android applications**.
- **Two-phase design:** an exploration phase learns app-specific operational knowledge; the deployment phase retrieves those generated documentation records when acting.
- **Observation:** the agent combines screenshots with Android XML structure and assigns numeric labels to interactive elements.
- **Actions:** tap, long-press, swipe, text entry, back and terminate form the operational action vocabulary.
- **Finding:** documentation generated from autonomous exploration or demonstrations materially improves task execution over acting without such app-specific knowledge, and demo-derived documentation is competitive with manually authored knowledge.

##### Author-stated / evidence-based limitations

Documentation can become stale when app UIs change, and exploration itself can be costly or unsafe. Ten apps remain a limited sample of the Android ecosystem.

---

#### Limitations

- **Limitation 1:** Preprint status; cite carefully.
- **Limitation 2:** Mobile apps differ from desktop web pages and APIs.
- **Limitation 3:** The agent may struggle with long-horizon tasks, dynamic layouts, and error recovery.

General thesis-level limitation:

```text
Improving one agent component is not enough for generalized web automation.
A robust web agent still needs grounding, planning, execution, verification, recovery, and safety.
```
