#### Concrete evidence verified from the full paper

- **Action interface:** BrowserAgent uses direct Playwright-style browser actions rather than requiring a site-specific API or brittle generated code program.
- **Memory:** explicit browser memory tracks useful page/evidence state across multi-step search.
- **Training:** supervised fine-tuning is followed by reinforcement fine-tuning for browser behavior.
- **Result:** **BrowserAgent-7B improves about 20% over Search-R1-Instruct** on HotpotQA/2Wiki/Bamboogle multi-hop browser evaluations in the paper.
- **Survey relevance:** it demonstrates that relatively small models can benefit substantially from an action space and training objective aligned to actual browsing behavior.

##### Author-stated / evidence-based limitations

The evaluation emphasizes multi-hop information seeking rather than arbitrary state-changing websites, and Playwright selectors/actions still face live-site drift.

---

#### Limitations

- **Limitation 1:** Results may be platform-specific.
- **Limitation 2:** UI and website changes can reduce transfer.
- **Limitation 3:** Training improvements must be paired with robust evaluation.

Training improvements in one environment do not automatically imply generalized web automation.
Agent learning still depends on perception, action grounding, evaluation validity, safety, and environment realism.
