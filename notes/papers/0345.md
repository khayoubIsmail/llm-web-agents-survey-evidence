#### Thesis-ready paragraph

Tur[k]ingBench: A Challenge Benchmark for Web Agents extends the benchmark landscape for LLM-based web agents by focusing on **crowdsourcing-style web task benchmark**. Its central contribution is that it evaluates agent behavior under conditions that are underrepresented in the core S5.1 P0 benchmarks. Specifically, it introduces or analyzes the setting: **32.2K instances across 158 tasks from natural HTML pages originally designed for crowdworkers.**. This matters for the thesis because generalized web automation and structured data extraction cannot be evaluated only by a single success score or by a single environment type. A robust web agent must generalize across websites, handle dynamic or multimodal content, maintain long-horizon context, avoid unsafe actions, and produce verifiable outputs. The paper's main finding is that **Models outperform random chance but still leave significant room for improvement on natural web-task pages.**. However, its limitation is equally important: **Crowdsourcing tasks differ from broad open-web navigation and structured extraction workflows.**. Therefore, the paper should be used as a P1 support reference that sharpens the S5.1 benchmark taxonomy and motivates later technical sections on grounding, planning, training, failure modes, safety, and deployment.

#### Concrete evidence verified from the full paper

- **Scale:** TurkingBench contains about **32.2K instances across 158 task types** created through naturalistic crowdsourcing.
- **Observation diversity:** it evaluates both textual and multimodal webpage contexts rather than forcing a single representation.
- **Purpose:** the benchmark stresses open-ended Web actions created by people rather than hand-designed microtasks.
- **Finding:** GPT-4-class and strong open multimodal models remain substantially below full task proficiency, with errors in grounding, instruction interpretation and long-horizon execution.
- **Survey role:** it provides evidence that expanding task diversity does not eliminate the same planning/grounding bottlenecks seen on smaller benchmarks.

##### Author-stated / evidence-based limitations

Crowdsourced tasks introduce distribution and quality-control choices, and benchmark pages remain a controlled collection rather than the entire live Web. Results depend on the supplied interaction interface and observation modality.
