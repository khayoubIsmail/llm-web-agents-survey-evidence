#### Thesis-ready paragraph

WorkArena++: Towards Compositional Planning and Reasoning-based Common Knowledge Work Tasks extends the benchmark landscape for LLM-based web agents by focusing on **enterprise web-agent benchmark extension**. Its central contribution is that it evaluates agent behavior under conditions that are underrepresented in the core S5.1 P0 benchmarks. Specifically, it introduces or analyzes the setting: **682 tasks corresponding to realistic knowledge-worker workflows.**. This matters for the thesis because generalized web automation and structured data extraction cannot be evaluated only by a single success score or by a single environment type. A robust web agent must generalize across websites, handle dynamic or multimodal content, maintain long-horizon context, avoid unsafe actions, and produce verifiable outputs. The paper's main finding is that **Reveals that even strong LLM/VLM agents struggle with enterprise workflows requiring compositional planning.**. However, its limitation is equally important: **Enterprise/ServiceNow-focused; high relevance to professional automation but not representative of all open-web or extraction tasks.**. Therefore, the paper should be used as a P1 support reference that sharpens the S5.1 benchmark taxonomy and motivates later technical sections on grounding, planning, training, failure modes, safety, and deployment.

#### Concrete evidence verified from the full paper

- **Compositional benchmark:** WorkArena++ expands the atomic WorkArena setting to **682 compositional knowledge-work tasks** that require multiple dependent subtasks.
- **Capabilities:** tasks exercise planning, problem solving, logical/arithmetic reasoning, retrieval and contextual application of enterprise information.
- **Ground truth:** the generator can produce thousands of valid task instances and reference execution structures while retaining programmatic final-state checking.
- **Finding:** agent success falls substantially as task composition/horizon increases, making planning and state tracking clearer bottlenecks than on atomic WorkArena tasks.
- **Survey role:** the pair WorkArena/WorkArena++ provides a controlled way to separate basic GUI competence from compositional knowledge-work planning.

##### Author-stated / evidence-based limitations

The benchmark remains ServiceNow-specific, and automatically generated task structures may not capture every ambiguity of organic workplace requests. Longer tasks also make failures harder to attribute to a single component.
